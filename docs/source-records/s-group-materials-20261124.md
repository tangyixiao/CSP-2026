## 1. 范围与口径 / Scope and method

**S 组四题。** 2026 年 CSP 第二轮提高组四道题是 `subway`、`crystal`、`hub`、`migrate`。本文只写这四题。

**四道题的官方测试数据都在仓库里**，随 2026-11-05 公告发布，共 180 个文件（`subway` 25 组、`crystal` 20 组、`hub` 20 组、`migrate` 25 组，每组一对 `.in`/`.ans`）。原始包 `CSP-S-2026-official.zip` 为 237,557,850 字节，SHA-256 `b30c09c093ef916aac78f83e152e626cd5fc87bfd9976f3c46eadb839d309c6c`；校验记录见 [official test data verification](docs/official-test-data-verification.md)。

**四道题的题面都在归档里。** `JS/S/JS-S00009/hub/hub.cpp`（178,163 字节，blob `76d1f4cfdd14`）不是源码，是一份 13 页的 PDF，内容就是整份 CSP-S 2026 第二轮试卷：四题题面、样例 1–2 的完整输入输出与解释、样例 3 及以后各自满足的测试点、四张数据范围表、以及「注意事项」。用 `pdftotext -enc UTF-8 -layout` 提取全文（27,703 字节），行号引用均以该文本为准：`crystal` L42–148、`subway` L150–357、`migrate` L361–520、`hub` L521–700。

同一份题面另有一处转录：`CQ/S/CQ-S00471/hub/hub.cpp` L22–129 是选手整段抄进去的题面注释。两份互校一致。§6 保留了 `hub` 题面的原文引用。

**100 KiB 上限的出处。** 题面「注意事项」第 4 条原文：`选手提交的程序源文件大小不得超过 100 KiB。`（题面文本 L32）。这条规定是 §4.5 体积普查的口径。

### 2.3 样例答案与官方测试点的三层关系

把上表与官方 180 组 `.ans` 逐组比对，得到三种不同情况，必须分开说。

**第一层：只有两个样例与官方测试点完全重合，且都是一个来源。** `migrate3.ans` 与官方第 3、4、5 组逐值相同（`[逐值]`）；`migrate6.ans` 与官方第 19、20、21 组逐值相同（`[逐值]`）。官方这些测试点本来就共用答案，所以同一条选手表在两个口径下都能对上。**这一层不能用来证明「选手拿到了官方答案」**——它同样能用「选手抄了样例」解释，而且后者更省。

**第二层：一个样例与官方只差一个值，且选手跟的是样例。** `migrate4.ans` 与官方第 12 组都是 12 个值，唯一差异在第 11 位：样例是 `5`，官方是 `7`。官方第 11 组该位也是 `5`，但它与样例还差在第 5 位（样例 `86669`、官方第 11 组 `233317`）。5 份携带该段的选手文件（`CQ-S00112`、`QH-S00045`、`QH-S00036`、`CQ-S00525`、`JL-S00309`）都写 `5`（`[逐值]`）。

**第三层：一个样例的值在官方里根本不存在。** `migrate5.ans` 的第 4 个值是 `716427`；官方第 15 组该位是 `314210`，第 17 组该位是 `718581`，25 组官方答案里没有任何一组出现 `716427`（`[逐值]`）。`CQ/S/CQ-S00112/migrate/migrate.cpp` 那一行写的正是 `716427`。

三层合起来只支持一个结论：这些表抄的是**样例答案**，不是官方测试点答案。上一轮材料里「官方第 12 组与第 11 组拼接而成」的说法不成立，已撤回；拼接不必要，直接抄 `migrate4.ans` 就能得到同一串。

### 2.4 覆盖率

「携带样例」= 文件里完整出现某个样例答案（≥2 值，按源码顺序作子序列匹配）；「携带官方」= 完整出现某个官方测试点答案（≥6 值，避免 0/1 短答案的巧合）。

| 题目 | 入选文件数 | 携带样例答案 | 携带官方答案 |
| --- | --: | --: | --: |
| `subway` | 25 | 21 | 0 |
| `crystal` | 15 | 0 | 0 |
| `hub` | 10 | 10 | 0 |
| `migrate` | 9 | 9 | 5 |

`subway` 里五份带全部七个样例：`AH-S00871`、`HA-S00294`、`HB-S00624`、`JS-S01159`、`GZ-S00439`。四份一个样例都不带：`CQ-S00045`、`CQ-S00135`、`CQ-S00382`、`CQ-S00501`——这四份是真在写算法或写日志的。

## 3. `c == 0` 这道门 / the `c == 0` gate

`subway`、`hub`、`migrate` 三道题的输入都以一个 `c` 开头。`hub` 的题面对它的定义是原文（`[文本]`，见 §6）：

> 输入的第一行包含两个非负整数 c, t，分别表示测试点编号与测试数据组数。特别地，若 c = 0，则该测试点为样例。

官方 180 组数据里 `c` 的实际取值范围：

- `subway`：1…25，**不含 0**
- `hub`：1…20，**不含 0**
- `migrate`：1…25，**不含 0**

本文逐份核对 61 个文件（59 份入选案例，另加两份为核对 `migrate` 补齐的同省文件）。其中 30 份带「表式分支」——一个 `if` 里至少两个整数相等判断；这 30 份里有 11 份的全部表式分支都挂在 `c == 0` 上：

| 文件 | 表式分支数 | 挂 `c==0` 的分支数 |
| --- | --: | --: |
| `AH/S/AH-S00871/subway/subway.cpp` | 7 | 7 |
| `AH/S/AH-S00939/subway/subway.cpp` | 6 | 6 |
| `CQ/S/CQ-S00112/migrate/migrate.cpp` | 6 | 6 |
| `JL/S/JL-S00211/subway/subway.cpp` | 5 | 5 |
| `GZ/S/GZ-S00446/hub/hub.cpp` | 5 | 5 |
| `JL/S/JL-S00102/subway/subway.cpp` | 4 | 4 |
| `CQ/S/CQ-S00112/subway/subway.cpp` | 3 | 3 |
| `GZ/S/GZ-S00008/subway/subway.cpp` | 3 | 3 |
| `GZ/S/GZ-S00446/migrate/migrate.cpp` | 3 | 3 |

| `JL/S/JL-S00196/subway/subway.cpp` | 2 | 2 |

按题面的定义，这些分支处理的确实是样例。这不是写错，是把题面读得太守规矩：题面说 `c = 0` 是样例，就给样例写了一条路，然后发现样例和测试点是两套答案。

## 4. 分题证据 / per-problem evidence

### 4.1 `subway`：七支分支，七份样例

`subway` 官方 25 组的参数域（`[逐值]`，脚本实测 `.in` 首行）：

- `c` = 1…25
- `n` ∈ {1, 2, 3, 15, 195, 495}
- `m` ∈ {7, 8, 72, 132, 192, 193, 493, 19302, 490542, 495492, 495495, 499999, 500000}
- `d` ∈ {2, 20}
- `q` ∈ {10, 200, 2000, 100000}

选手键里出现的 `n == 480`、`m == 481 / 479521 / 18721`、`q == 2 / 90000` 全部不在官方参数域里（`[逐值]`）。而七段样例答案的载体各写一式：

| 载体 | 文件 | 说明 |
| --- | --- | --- |
| 并列 `if` + 四列键 | `HB/S/HB-S00624/subway/subway.cpp` | 七支分支，L11–L17 |
| 库表 + 循环匹配 | `HB/S/HB-S00440/subway/subway.cpp` | 四个数组当键，`string ans[7]` 只初始化 4 格 |
| C 数组初始化器 | `JL/S/JL-S00084/subway/subway.cpp` | `int type3[500] = {341, 667, …}` |
| 嵌套树 | `GZ/S/GZ-S00439/subway/subway.cpp` | 按 `c` → `n` → `m` → `q` 逐层嵌套 |
| 逐行 `printf` | `JS/S/JS-S01159/subway/subway.cpp` | 272,230 行，仅 8 个 `if` |
| 跨行字面量 | `JL/S/JL-S00102/subway/subway.cpp` | 单个字符串字面量横跨 8.9 万物理行 |
| 单语句 `cout` 链 | `AH/S/AH-S00939/subway/subway.cpp` | 6 支，每支一条 `cout` 链接完 |

**`HB-S00624` 的括号。** L17 起手是 `if(n==480 && m==479521 && d==2 && q==90000{`——`if(` 在碰到 `{` 之前没有闭合（`[文本]`）。同一文件的 L14 是 `if(n==480 && m==481 && d==20 && q==90000){`，完好。也就是说七兄弟里最小的那个少了一个右括号，而它的答案串有 1,224,774 个字符。

**`GZ-S00409` 的键退化。** 前两支用 `n==2`、`n==3`，第三支用 `n==15` 打出 26 个值——这 26 个值与七份样例、25 组官方答案都对不上，是第三种来源（`[逐值]`）。第四支 `if(m==481)`、第五支 `if(m==18721 )`（`m` 后面多一个空格，不影响语义），第六支 `if(d==20)`——任何 `d == 20` 的输入都会打出 `subway6.ans` 那 90,000 个值（`[推断]`）。L35 是 `//	打不动了`，紧跟 `return 0;`。同一文件里还有 L5 `//	提交时一定要解除注释！`、L9 `//	第一行`。

**`JS-S01159` 的四支 `if` 与两处把答案头当参数。** 文件只有 8 个 `if`：L219 `if(n==480 && m==481)`、L90221 `if(n==480 && m==18721)` 两支与样例参数对得上；L92223 `if(n==97 && m==905)` 的 `97 905` 正是 `subway6.ans` 的头两个值；L182225 `if(n==112644344117)` 的 `112644344117` 正是 `subway7.ans` 的第一个值。后两支是死分支——抄表时把答案的头几行贴进了条件槽（`[文本]`）。

**`JL-S00102` 的两个首位数字。** 该文件与 `subway6.ans` 逐值比对为 89,998 / 90,000 相同，两处各掉首位：段内 0 基位置 182 的 `26378` 写成 `6378`，位置 449 的 `3909` 写成 `909`（`[逐值]`）。它同时是「裸换行写进字符串字面量」的最大样本——`cout<<"` 从 L18 开到 L89506 才闭合，字面量里是真实的换行字节，标准 C++ 不允许（`[文本]`）。

**跨省同指纹。** 以 `subway4.ans`（200 值）为参照，字节级完全相同的四份分属四省：`AH-S00871`、`HB-S00624`、`GZ-S00409`、`JL-S00211`（`[字节]`）。七段全字节同的是两份（`AH-S00871`、`HB-S00624`）。这些是分布事实，不构成传播链。

**贴一半的谱系。** 只带样例 3 前若干值的五份：`JL-S00132` 前 194 值、`HB-S00535` 前 184、`QH-S00036` 前 79、`JL-S00309` 前 31；`GZ-S00409` 是相反的——只贴末 26 值，缺头部 `341 667`（`[逐值]`）。
