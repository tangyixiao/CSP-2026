# Working on CSP-2026

- Inspect the active Git state and existing workspaces; preserve dirty work and
  other tasks. Reuse a suitable checkout and compatible tools before creating a
  clone, worktree, dependency installation or backup.
- Keep disposable scripts, logs, screenshots and intermediate data in this
  task's `work/`; keep requested deliverables in `outputs/` or the host's named
  artifact location. Do not scatter directories at drive roots or beside projects.
- Use the existing task record to track paths and processes. Do not write routine
  plans, handoffs or success reports solely to document execution.
- Before substantial downloads, extraction, packaging or builds, inspect free
  space and peak simultaneous copies. Follow `project.json` resource budgets.
  Bound caches and logs; run one heavy local operation at a time. Use CI for full
  archive packaging instead of downloading all missing blobs to a partial clone.
- At completion or abandonment, inspect task-owned resources and stop unneeded
  task-owned processes. Confirm ownership, absolute boundaries, active consumers,
  symlinks and unique work before cleaning disposable files. Preserve required
  work and use recoverable worktree archival. Do not use broad deletion, forced
  worktree removal, `git clean` or `reset --hard` as cleanup shortcuts.
- Retained temporary resources need a purpose and removal condition. A move or
  recycle operation is not a verified disk-space recovery.
- Archive original contestant paths, filename casing and bytes, including empty
  files, invalid code, source-named binary submissions and unusual names. Describe
  actual content types and supplied-package provenance separately. Keep passwords
  and credentials out of Git, releases, public issues and logs.
- Use English repository metadata. Public website copy is Chinese and English;
  keep project facts in `project.json` and derive coverage from Git/catalog data.
  Do not copy template example-project links or replace third-party licenses.
- The four project pages introduce CSP-2026 and how to use it. They are not a
  template advertisement, file inventory or agent-policy display. New visual
  directions need a real-content desktop/mobile concept and explicit human
  approval. Publish requested review previews under `/preview/`; promote the
  formal homepage only after approval. Routine fixes need no repeated approval.
- Validate actual Chinese typography, hierarchy, spacing and key states at
  desktop and mobile sizes. Functional tests alone do not certify visual quality.
- Keep local tests, CI, source merge, platform configuration, deployment, download
  verification and published releases distinct. Verify current evidence before
  reporting each state. Archive sources are preserved, not compiled or executed.

GitHub does not automatically distribute these rules to every AI client. Global
client instructions must be configured and verified separately.
